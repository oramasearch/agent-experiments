### Conversation history is bound to its workspace, and bounded — #37

- The pod serves every workspace and looked history up by conversation id alone, so another workspace that knew the id could read or write into it, and new ids grew memory without limit (#35).
- New `conversations.py`: history is keyed by customer, the checked workspace path (`lake_url`), `workspace_id` and `user_id` when the turn has them, and the conversation id. The store holds at most 256 conversations (least recently used dropped first), expires a conversation idle for an hour, and keeps each history to its system prompt plus at most 60 messages and 200,000 characters, dropping the oldest whole exchanges so a tool reply never loses its call.
- `run_turn` works on a copy of the history and stores it back whole under the lock.

### The public-tree cleanup — #41

Nothing internal is left in the files that will be published: `.public-exclude` was added and then removed again once the agent files were rewritten to ship publicly; issue links became plain text, the release notes name no environment, and "private" wording about the repository and its image is gone. Documentation and one Dockerfile comment only.

### The licence — #40

Everything in this repository that Orama wrote is under the MIT licence. Contributors sign `CLA.md` once. `THIRD_PARTY_LICENSES` lists every runtime dependency with its licence text; none is incompatible with MIT distribution.

## Known issues

Security-relevant first. All open at this tag.

1. #42 (release blocker for publishing): the image is built on `python:3.12-slim`, which bundles GPL and LGPL userland, so **the image is not published**. It is built and kept in the project's non-public Docker Hub repository until it moves to a scratch base with static binaries.
2. #3: the task's workspace is not passed explicitly on data-plane calls. Lake scopes the task credential to the task's workspace.
3. #33: in an end-to-end run against lake v0.8.1 the final turn did not explain the experiment (empty answer).
4. #20: the agent reads `EXPERIMENTS_AGENT_MODEL` and not the operator's `AGENT_MODEL`.

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes run the operator's default image of this agent; the changes since v0.2.2 are proven by the test suite only. Moving a Lake to `:v0.3.0` is a separate operator change.
